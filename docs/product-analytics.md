# Продуктовая аналитика Chunki

## Аудит исходной системы

| Источник | Что хранится | Что можно восстановить |
| --- | --- | --- |
| `users`, `sessions` | Аккаунт и сессии авторизации | Дата регистрации. Сессия авторизации сама по себе не означает посещение или учебное занятие. |
| `placement_tests` | По одной записи на сохранённый тест, уровень, цель, время проверки и подготовки программы | Завершённый тест и подготовку программы. Начатые, брошенные и повторно открытые тесты раньше могли существовать только в локальном черновике. |
| `user_topics`, `program_topics` | Назначение, каноническая тема, источник и текущее состояние | Админский список читает активные назначения и сортирует по `user_topics.updated_at`. Email берётся из `users`. Название и категория берутся из `program_topics`. «Изучить», «Ждёт переподтверждения» и «Подтверждено» обозначают состояние. Источники — тест, обнаруженная слабая тема или самостоятельный выбор. Дата — последнее обновление строки. Несколько действий над темой могут привести к одной строке. |
| `topic_attempts` | Сохранённая попытка и её проверка | Запуск проверки, результат и время оценки. Открытая попытка возобновляется. Успешная первая проверка ставит повторение. Успешное переподтверждение переводит тему в освоенные. Неуспешная проверка возвращает в изучение. Запись о попытке сама по себе не показывает, был ли прочитан урок. |
| `daily_learning_plans` | Снимок повторений и одной новой темы на календарный день | Состав плана. Попытка после формирования плана закрывает шаг, при этом учебный статус зависит от результата проверки. |
| `chunk_progress` | Одна строка на пользователя и чанк, накопительные счётчики и последние даты | Текущее состояние и накопительный итог. Коллекция может содержать чанк, который есть и в другой коллекции. Ни прогресс, ни серверные запросы каталога не подтверждают, что человек увидел коллекцию или карточку. |
| Комиксы | Сервер хранит материал. На клиенте все реплики показываются сразу. Комикс открывается из карточки или вкладки «Комиксы». | Истории показа раньше не было. Нажатие «Продолжить» и закрытие крестиком теперь учитываются по-разному. |
| `study_reminders` | Устройство, подписка, расписание и последний обработанный локальный день | Текущие подписки. `last_sent_on` выставляется при обработке, включая пропуск по плану или ошибку. По этой колонке нельзя восстановить успешные отправки. |
| `ai_call_logs` и HTTP-логи | Вызовы модели и технические запросы | Пригодны для диагностики. Запрос проверки, повтор сети и health check не равны действию ученика. |

**Проверка данных.** Структура и сценарии проверяются на локальном PostgreSQL с миграциями и тестовыми аккаунтами, включая переход со старых схем. Присланный фрагмент production-логов состоит из `GET /api/health`. Он не даёт выборки по пользователям или базе. Для проверки реальных объёмов и качества исторических данных потребуется доступ на чтение к production-БД. Данные пользователей из production при разработке не копировались.

## Каталог событий

| Область | Единица учёта |
| --- | --- |
| Вход, тест уровня | `app_opened` после появления приложения на переднем плане, `placement_started` с меткой первый или повторный, `placement_completed` при сохранении, `placement_result_viewed` при показе результата. Начало и завершение связываются ID отправки. |
| Программа и тема | `program_prepared`, `program_opened`, `topic_opened` с контекстом, `topic_study_started` при переходе к упражнениям из загруженного урока, `topic_check_started` и `topic_check_completed` по ID попытки. Результат содержит оценку, факт прохождения и тип проверки. Прямой запуск проверки учитывается без перехода из урока. |
| Коллекции и карточки | `collection_opened`, `deck_started`, `card_viewed`, `deck_completed` по фактической навигации. `card_reviewed` при приросте серверного счётчика, `card_first_mastered` при первом подтверждении в речи. Клиентская колода связывается ID занятия. |
| Комиксы | `comic_opened` означает, что диалог показан, `comic_completed` означает нажатие «Продолжить». У повторного открытия будет новый ID прохождения. Факт прочтения каждой реплики интерфейс не измеряет. |
| Напоминания | `reminder_enabled`, `reminder_disabled`, `reminder_schedule_changed` при изменении сохранённых настроек. `notification_permission_granted` или `notification_permission_denied` только после запроса разрешения. Для допущенной планом отправки отдельно сохраняются время по расписанию, попытка, принятие отправки провайдером, ошибка и клик. |

## Хранение и границы данных

- `product_events` дописывается по ключу «пользователь + ID события». Время события и время приёма хранятся как `timestamptz`. Клиент передаёт только поля из закрытой схемы, в журнале нет ответов учащихся, токенов подписок, email, IP или текста комиксов. Email и название материала добавляются при чтении в админке.
- `product_activity` объединяет журнал с сохранёнными фактами регистрации, тестирования и проверки тем. Исторические факты читаются из исходных таблиц и остаются доступными, пока существуют эти записи. Удаление аккаунта удаляет относящиеся к нему данные.
- Прогресс и настройки напоминаний хранятся в исходных таблицах. `notification_deliveries` хранит результаты отправки отдельно от подписки. Запланированной считается отправка, которую диспетчер допустил к обработке по правилам плана, а не теоретическая сумма будущих уведомлений. Подтверждения доставки на устройство Web Push не даёт.
- Клиентские записи переживают переходы, перезагрузку и повтор запроса при доступном хранилище браузера. Очередь ограничена 300 записями на пользователя и 30 днями. Если браузер заблокировал хранилище или вкладка закрыта до повторной отправки, часть клиентских событий может потеряться. Действия, подтверждённые состоянием сервера, от очереди не зависят.
- В обычном интерфейсе соседние темы показаны в модулях программы. Код API самостоятельного назначения проверяет тариф и наличие темы, при этом не проверяет принадлежность к одному из модулей ученика. Аналитика описывает фактически начатые попытки и не меняет это правило доступа.

## Метрики и админка

Раздел «Аналитика» доступен администраторам. Есть обзор, обучение, контент, уведомления и хронология. В хронологии можно выбрать пользователя из раздела «Пользователи» или отфильтровать по email, ID, событию и материалу. Сводный период использует календарь Москвы. Для выполнения ежедневного плана используется часовой пояс, который был сохранён при его формировании.

- **Активация.** Среди новых регистраций за период доля пользователей хотя бы с одним подтверждённым результатом: успешно проверенная тема, завершённая колода, впервые подтверждённая карточка или завершённый комикс. Показывается числитель и знаменатель.
- **Возвращаемость.** Доля когорты с наблюдаемым действием ровно в D1, D7 или D30. В знаменатель входят пользователи, для которых день уже завершился. Дата регистрации — D0.
- **Обучение.** Воронка для когорты регистрации от сохранённого или начатого теста до первой успешной проверки рекомендованной темы после теста. Для исторических результатов завершённый тест подразумевает начало. Общее количество подтверждённых действий и доли завершения считаются отдельно. Сессии для долей связываются по ID.
- **Следование плану.** Доля непустых планов прошедших локальных дней, для которых все нужные попытки проверены между формированием плана и его локальным дедлайном. Старые планы без часового пояса исключены.
- **Контент.** В своём типе материала ранжируется по завершениям, учебным действиям и затем открытиям. Возврат к материалу означает несколько открытий или действий одного пользователя за выбранный период.
- **Напоминания.** CTR — число отправок, принятых провайдером и получивших клик, делённое на число принятых отправок. Уникальные пользователи считаются отдельно. Сам по себе CTR не измеряет причинный эффект напоминаний.

## Миграция и проверка

Миграция `0042_product_analytics.sql` выполняется после `0041_study_reminder_days.sql`. Она добавляет журнал и его индексы, хранение отправок, представление исторических фактов, триггеры на будущие изменения и поле часового пояса. Прошлые открытия и успешные отправки не дорисовываются. Проверки есть в `analytics.integration.test.ts` и `reminders.integration.test.ts`.
