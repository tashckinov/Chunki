# Аудит интеграции аналитики и CEFR

## Что подтвердилось

| Участок | Наблюдение и исправление |
| --- | --- |
| [Назначение и проверка](../apps/server/src/modules/program/repository.ts) | Самостоятельному назначению было достаточно тарифа и ID из каталога. После этого проверка владельца по UUID пропускала открытие материала, запуск и сдачу упражнений. Теперь самостоятельная тема должна входить в доступный модуль. Правило действует для уже сохранённых назначений, а также для рейтинга и пожеланий, использующих тот же поиск назначения. Рекомендации доступны напрямую. Материалы, попытки и прогресс сохраняются. |

Теперь основанием служит активная рекомендация из теста или найденная по результатам проверки. Каталог до диагностики по-прежнему отдаёт только метаданные. |
| [История действий](../apps/server/migrations/0042_product_analytics.sql) | Идентификаторы уроков сохранялись, однако ID цели и назначения отсутствовали. Соединение со свежим каталогом перенесло бы прошлые результаты при переатрибуции урока. |
| [Запросы аналитики](../apps/server/src/modules/analytics/report.ts) | Активность и возвращаемость использовали разные наборы событий. Теперь список общий. В заданных периодах есть верхняя граница «сейчас». Счётчики тестов и подписи воронки теперь явно различают события, попытки и уникальных пользователей. |

Миграция [0043](../apps/server/migrations/0043_analytics_curriculum_objectives.sql) сохраняет цель CEFR при первом назначении. Клиентские открытия и новые попытки наследуют цель назначения. Попытка также запоминает источник назначения и использует его для начала и завершения. Перепривязка урока применяется к новым назначениям и не меняет принадлежность старых назначений, их открытий и попыток. Новая и прежняя связь различимы в отчёте по урокам. Существующие назначения и попытки без снимка цели остаются без атрибуции, включая дальнейшие действия по старым назначениям. Для них по-прежнему доступны общие показатели и показатели урока. Миграция не добавляет задним числом назначения и открытия.

## Что объясняет показанные цифры

- **Семь завершённых тестов и шесть пользователей в воронке.** Сводка считает строки проверенных тестов, воронка считает уникальных пользователей из когорты регистраций. Один человек мог сдать тест дважды, либо одна попытка могла принадлежать аккаунту вне когорты. По одним итогам причину определить нельзя.
- **Ноль записанных запусков при наличии завершённых.** Завершения читаются из базы тестов, запуски доступны с момента внедрения клиентского события. В воронке сохранённый результат служит свидетельством, что человек дошёл до теста. Наблюдаемый запуск показан отдельной строкой. Это совместимо с ранним развертыванием сбора, но не подтверждает его исправность на production.
- **Шесть активных и один с учебным действием.** Активность включает посещение, открытие материала и тест уровня. Учебный показатель использует более узкий перечень действий и выбранный период.
- **Ноль открытий при наличии действий.** История серверных попыток старше клиентского сбора. Возможны также завершение начатого до выбранного периода и неполная доставка клиентской телеметрии. Открытия из проверок не восстанавливаются.

## Определения показателей

Для выбранного периода начало — полночь Москвы за `N − 1` календарных дней до текущей даты. Конец — текущее время. Активные за 1, 7 и 30 дней используют свои календарные окна. Количество пользователей считается по уникальному `user_id`.

| Показатель | Источник и формула | Единица и ограничения |
| --- | --- | --- |
| Регистрации, новые | Все строки `users`; для новых — с `created_at` внутри периода | Пользователи. Удалённые аккаунты отсутствуют. |
| Активность D1/D7/D30 | Уникальные пользователи по событиям посещения, теста, программы, перехода к упражнениям, открытия темы, коллекции или комикса, старта колоды или завершённого учебного действия | Пользователи. Неполное историческое покрытие клиентских действий. |
| Учебные действия и ученики | Количество завершённых проверок тем, завершённых колод и комиксов, ответов по карточкам и первых подтверждений карточек; отдельно уникальные пользователи по этому же набору. Интенсивность — первое число, делённое на второе | Действия, пользователи и действия на пользователя. Неуспешная проверка — тоже учебное действие. |
| Запуски и завершения тестов | Количество `placement_started` из клиентского журнала и сохранённых записей `placement_tests` по отдельности | События запуска и попытки. Старые запуски неизвестны. Повторный тест добавляет попытку. |
| Воронка | Когорта зарегистрированных за период. Дошли до теста — есть запуск или результат; наблюдаемый запуск — есть соответствующее клиентское событие; завершили — есть результат; дошли до урока — есть успешная первичная проверка рекомендации после результата теста | Уникальные пользователи на шаге. У каждого шага различается историческое покрытие. |
| Активация | Пользователи из когорты с успешной проверкой темы, завершённой колодой или комиксом либо первым подтверждением карточки / все пользователи когорты | Доля пользователей. Часть старых действий отсутствует. |
| Возвращаемость | Пользователи из когорты с событием активности ровно в D1/D7/D30 / все пользователи когорты, для которых этот день уже завершился | Доля пользователей. D0 — местная дата регистрации. |
| Завершение занятий | Начатые в периоде колоды, комиксы или проверки, для которых найдено последующее завершение по ID занятия/попытки / все соответствующие старты | Доля занятий по типу. В старых данных нет стартов колод и комиксов. |
| Следование плану | Непустые планы прошедших локальных дней со всеми проверенными шагами до полуночи / все такие планы с известным часовым поясом | Доля планов. Старые планы без часового пояса исключены. |
| Контент | События открытия, учебного действия и завершения по ID материала. Уникальные ученики — по событиям материала. Вернулись — действия с материалом как минимум в два местных календарных дня | События и пользователи. Открытия и завершения не являются обязательной парой в одном окне. Завершение комикса учитывается и как учебное действие. |
| Назначения CEFR | Новые `topic_assigned` с зафиксированной целью. Считаются записи и уникальные пользователи. Текущие связи уроков считаются отдельно по `program_topics.curriculum_id` | Назначения, пользователи и уроки. Повторное использование старого назначения не считается новым. |
| Активность CEFR | Открытия — `topic_opened`. Приступили — уникальные пользователи с переходом от урока к упражнениям. С активностью — уникальные пользователи с открытием, переходом или попыткой | События и пользователи. Можно выделить назначенные цели с нулевой наблюдаемой активностью. |
| Проверки CEFR | Завершённые попытки и отдельно неуспешные. Сдали — уникальные пользователи с любой успешной попыткой, освоили — с успешным переподтверждением. Первичные проверки делятся по источнику; переподтверждение считается отдельно | Попытки и пользователи. Сумма уникальных по урокам может превышать число по цели. |
| Напоминания | Текущие подписчики — уникальные пользователи из `study_reminders`; отправки, ошибки и клики — строки `notification_deliveries` с соответствующими отметками; CTR — клики среди принятых провайдером / принятые провайдером | Пользователи, отправки и доля отправок. Провайдер не подтверждает доставку на устройство. |

## Проверка данных

Проверка выполнена на локальной базе PostgreSQL с применением миграций и тестовыми аккаунтами. Доступного read-only подключения к production-БД в рабочем окружении не было. Версии миграций, реальные объёмы, дубликаты и сверка с цифрами production-панели остаются непроверенными. Приведённые объяснения описывают поведение кода и не утверждают причину конкретных production-счётчиков.
